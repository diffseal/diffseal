# TerraTrust v0.3.0-beta release draft

Prepared for owner review. No tag or release has been created.

This beta adds parsed application code in Go, TypeScript, Python, Java, Kotlin and C#, AWS-derived permission mappings, deployment mapping, unsigned evidence exports and an opt-in offline module cache. Parser assets remain local. They load only when the scanned files need them and are stored compressed to reduce the Action package.

## Main changes

- `terratrust evidence --since 2026-10-01 --until 2027-01-01 --repo ./infrastructure --out-dir ./quarter-pack` exports an unsigned audit period. It includes caller-supplied approvals when `--approvals` is provided.
- `terratrust modules fetch --repo ./infrastructure --cache ./module-cache` is an explicit network step for public modules. Commit the generated lock with the configuration. Replay and check-app accept `--module-cache` and never download modules implicitly.
- Rendered Kubernetes and limited ECS deployment configuration can connect app files to a role. Dynamic build and deployment behavior remains unresolved.
- Provider aliases, Terraform JSON configuration, lifecycle guards in zero-instance modules and customer-managed policy instances have regression fixes.
- The PR comment states the gate in its heading and lists what blocks or needs review in a GitHub alert box. Granted calls and passing checks are collapsed.
- CI verifies source, tests and committed Action assets. Demo scenarios run through the bundled Action.

## Upgrade notes

Replace the complete vendored Action folder, including every parser asset, rather than only action.js. The new assets are compressed files referenced by the bundle. Retain their licence notices. The Action uses Node 24; the CLI bundle should also be run with Node 24.

Anything that parses the Markdown report must be updated: the `**Gate: X**` line is now the `## TerraTrust: X` heading. Use the `gate` output or `--json` for automation.

Programmatic callers must await scanApp, checkApp, replayCommit and evidencePack. Low-level synchronous extractors need their languages prepared first. Module cache users should review docs/research/module-cache.md before enabling the network fetch step. A committed lock and its cached historic pins are needed for reproducible offline replay.

The licence is FSL-1.1-ALv2. Read LICENSE and CONTRIBUTING.md before distributing changes or contributing.

## Advisory pilot

Run `bun run build`, then `bun scripts/prepare-pilot.ts dry-runs/pilot-vendored-v0.3.0-beta` to prepare a new folder. It contains a local Action, complete dist assets, parser notices, VERSION files, a SHA-256 manifest and an advisory workflow. Copy those files into the private infrastructure repository only after review.

The workflow uses `./.github/actions/terratrust`, `mode: pr`, `advisory: 'true'`, `strict: 'false'` and `continue-on-error: true`. BLOCK findings remain visible without failing the pilot job. This preparation does not install the pilot, publish anything, change repository settings or create a tag.

## Limits

This is static AWS analysis. Unknown state, provider values, unsupported calls and dynamic deployment inputs still need review. Thirty-five AWS operations remain explicitly unresolved. Optional permissions are modeled only for documented selectors. Module fetching does not yet support private credentials or every Terraform source transport. Evidence packs have no signature and their approvals are not independently verified.

The owner should review the final integration report and private regression output before tagging. Use the existing release procedure after approval. See CHANGELOG.md for both beta versions.
