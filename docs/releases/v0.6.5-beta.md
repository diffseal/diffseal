# Diffseal v0.6.5-beta

Fixes from a launch review on 2026-11-04. On the three measured sets, 2,175 commits, no gate changed and no BLOCK is judged false. `docs/STATUS.md` has the numbers.

## Changes

- IAM policy updates. An old grant counts as revoked only when the new policy does not certainly still allow it. Before, widening `dynamodb:PutItem, dynamodb:GetItem` on a table to `dynamodb:*` on `*` said the callers would get AccessDenied, which was false. That row is now INFO. Anything not certain, such as a condition or a Deny that may match, is still reported as revoked. An inline user or group policy whose grants cannot be compared is now LOW, as role and managed policies already were.
- Trusted upload settings on a push. The reusable upload workflow reads `replay` settings from `.diffseal.json` at the branch head before the push. Before, it read them from the pushed commit itself, so a direct push that edited `replay.rootsUnder` narrowed its own record. After a force push, or on a new branch, it reads them from the first parent of the pushed commit.
- The README's install snippet sets `advisory: 'true'`.
- `docs/guide/verify.md` shows how to check a signed pack without Node.js, with `shasum` and OpenSSL 3, and which checks of `diffseal verify` that leaves out.

## What to expect

The same gates as v0.6.4-beta on the measured commits. Some IAM rows move between LOW and INFO; the default gate reads neither. Evidence uploads for direct pushes use the settings the branch had before the push.

## Upgrade notes

1. Change `diffseal/diffseal@v0.6.4-beta` to `diffseal/diffseal@v0.6.5-beta`, and the reusable workflow to `diffseal/diffseal/.github/workflows/upload.yml@v0.6.5-beta`.
2. Update the CLI with `npm install -g diffseal@beta`.

See CHANGELOG.md for all versions.
