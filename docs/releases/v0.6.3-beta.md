# Diffseal v0.6.3-beta

Accuracy fixes from replaying a third set of 750 commits of 10 public Terraform repositories that earlier releases were not tuned on, and the full report of every Action run kept as a workflow artifact. On those commits a production database deletion that was only reviewed now blocks, two changes that passed are now reviewed, and 46 unneeded REVIEWs from one repository are gone. No BLOCK is judged false on any of the three measured sets, 2,175 commits in all. `docs/STATUS.md` has the numbers.

## Changes

- Workspace names. A root that derives its environment from `terraform.workspace` by removing a part (`trimprefix`, `substr`, `replace`, `trimsuffix`, `split`, `regex`) is evaluated in full workspace names built from that part and the keys the configuration uses, such as `app-production`. Before, bare keys like `production` were evaluated, which do not exist.
- Deleting or replacing a resource whose `prevent_destroy` guard was removed in the same change is reviewed.
- Deleting or replacing a Glue catalog database or table is reviewed.
- Replacing an EC2 instance is reviewed.
- An engine version change on an RDS instance or Aurora cluster is reviewed.
- A value read from a map by a key not known statically is compared per key, so an edit to one environment no longer marks every resource that reads the map as changed.
- `yamldecode()` decodes plain YAML documents, so changes driven by a YAML file are shown.
- Two unknown values are no longer proven equal when what they come from changed.
- The Action writes `report.json`, `report.md` and `change-record.json` to the directory in its new `report-dir` output. The trusted upload workflow keeps them as the `diffseal-<short sha>` artifact of the run for 90 days (`retention-days` changes this). A change record trimmed to fit the upload limit names that artifact and the file's SHA-256.

## What to expect

A few more changes land in REVIEW: EC2 replacements, Glue deletions, removed `prevent_destroy` guards and database engine upgrades. A root that derives its environment from a workspace name in a way Diffseal cannot rebuild is reviewed as not evaluated, and the line names the root. Repositories that pick per-environment settings from a map by an unknown key see fewer REVIEWs.

## Upgrade notes

1. Change `diffseal/diffseal@v0.6.2-beta` to `diffseal/diffseal@v0.6.3-beta`, and the reusable workflow to `diffseal/diffseal/.github/workflows/upload.yml@v0.6.3-beta`.
2. Update the CLI with `npm install -g diffseal@beta`.
3. Optional: if you call the Action directly and want the reports kept, add an `actions/upload-artifact` step for the `report-dir` output. `docs/guide/action.md` shows it.

See CHANGELOG.md for all versions.
